# Propose Change

1. 按 SKILL.md 完成 capabilities、工作区、principles、图集和 reference 检查。
2. 确认变更具有建模影响；普通实现修复不强行创建图或 Change Pack。
3. 当前无活动 Pack 时运行 `change new`；并行变更使用独立工作区。
4. 收集事实、推断和未知，填写 proposal、decisions、tasks 与 AC。
5. 先给出视图清单并遵守视图预算，再写 overlay 与 `change.yaml`。
6. 按合同解析并校验 desired；需要视觉证据时运行 `change render`。
7. 运行 `status`、`validate` 和 `diff`，修复所有结构与内容事实问题。
8. 规则细节以 `references/change-pack-contract.md` 为准。

结束时进入 review model，不实施架构敏感代码。
